# Features Round 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship ten owner-approved features in five releases (1.19.0 to 1.23.0): version history and rollback, test condition, deadlines, backfill, a dependency graph, a calendar, Teams/PagerDuty/ServiceNow, an approval gate, snippets, and cost and performance.

**Architecture:** Each feature is a new server module under `app/search_orchestrator/bin/so/` (pure logic plus thin route handlers registered in `api._routes()` with a lazy import, like `preview_api`) and new UI files with an API module per feature under `ui/src/api/`. `engine.py`, `api.py`, `state.py` and `BuilderPage.tsx` only gain call sites. Engine features (deadlines, backfill feeding, approvals) follow the existing restart rules: deterministic keys, hooks submitted before the run save that records them, decisions stored before they take effect.

**Tech Stack:** Python 3.9–3.13 (Splunk's), pytest with `tests/fakes.py`; React 18 + TypeScript, `@splunk/react-ui` 5.18, `@splunk/themes`, `@dagrejs/dagre`, Jest + RTL; Dashboard Studio JSON for Run health.

**Spec:** `docs/superpowers/specs/2026-11-17-features-2-design.md` (core: `docs/superpowers/specs/2026-11-05-search-orchestrator-design.md`; flow editor: `2026-11-16-node-editor-design.md`, `2026-11-16-node-editor-2-design.md`; conditions: `2026-11-17-spl-conditions-design.md`).

## Global Constraints

- Opening and saving an unchanged job never changes it: no new field is written with its default value, no version is added, `layout` is untouched. Jobs without the new fields behave exactly as before.
- Engine changes are restart-safe and idempotent: deterministic keys, hooks submitted before the run save that records them (`actions.submit` rows are idempotent), decisions stored before they take effect, one whole-document write per change.
- The server validates everything the client checks; every error message says what is wrong and how to fix it.
- Copy: sentence case; buttons start with a verb; destructive actions confirmed in a `Modal` titled with a question; no `Badge`, `Chip` or filled pill for any status (StatusText: icon + words + text colour).
- Colours only from theme tokens (`useSplunkTheme()`), no hex literals; every pointer action has a keyboard path.
- Files at most 600 lines. `engine.py` (1357), `api.py` (1135), `state.py` (545) and `BuilderPage.tsx` (595) gain call sites only (net ≤ 30 lines each per task, ≤ 5 for `BuilderPage.tsx`); new logic goes in the files this plan names. `ui/src/api/types.ts` stays ≤ 600 lines: new types go in the feature API modules.
- No new npm or Python dependencies.
- New global names get rules in `scripts/variant_rename.py` in the task that adds them: capability `orchestrator_approve`, role `orchestrator_approver_role`, pages `calendar` and `dependencies`, macro `orchestrator_search_process`, and new `| orchestrate` text in `orchestrate.py`/`searchbnf.conf`/`model.py`. `tests/test_package.py::test_variant_package_renames_every_global_name` must pass after every task.
- New KV collections (`so_job_versions`, `so_backfills`, `so_snippets`) are declared in `default/collections.conf`, restricted in `metadata/default.meta` (`access = read : [ admin, sc_admin ], write : [ admin, sc_admin ]`) and added to `COLLECTIONS` in `tests/test_package.py`.
- New REST routes are at most three segments under `orchestrator/` (no `web.conf` change). Query parameters arrive in `body` for GET, as for `runs`.
- Commands (repo root): `python3 -m pytest -q`; `cd ui && NODE_OPTIONS= npx jest`; `cd ui && NODE_OPTIONS= npm run typecheck`. All green at the end of every task.
- Commit after each task; the message's last line is `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.
- Each release ends with docs (`docs/user-guide.md`, which is also the in-app Help; `docs/admin-guide.md`), `CHANGELOG.md`, `default/app.conf` (`version`, `[launcher] version`, `build` + 1; 1.18.2 is build 19), `app.manifest` version, both packages and AppInspect cloud at 0 errors and 0 failures.

## Review Focus

1. **An unchanged job round-trips.** Open a job saved by 1.18.2 (no `deadline`, no approval steps, no versions), save it without edits: the stored document and its hidden searches are identical and no version is written; the first *edited* save writes version 1 (the old job) and version 2. Tests in Task 1 (`test_unchanged_save_writes_no_version`, `test_first_edit_of_old_job_writes_baseline`) and Task 9 (`deadline fields left empty keep the job unchanged`).
2. **Restart in the middle of a backfill feed.** The engine dies after `create_run` and before the backfill's `next` is saved: the next tick creates no duplicate run and skips no slot. Test in Task 11 (`test_feed_survives_crash_between_create_and_save`).
3. **Two decisions for one approval.** Two approvers click within the same tick, or a decision lands in the tick the timeout expires: exactly one decision takes effect, the other is audited `approval_ignored`, hooks fire once. Test in Task 22 (`test_second_decision_is_ignored`, `test_decision_and_timeout_in_same_tick`).
4. **Finish-by across midnight and DST.** A run scheduled 07:00 with finish by 06:00 is due 06:00 the next day; on the Europe/Oslo spring-forward day 06:00 local is 04:00 UTC. Test in Task 7 (`test_finish_by_next_day`, `test_finish_by_dst`).
5. **Restoring a version that no longer validates.** The version names a saved search or destination that was deleted: restore returns 400 `job_invalid` with the issues, the job, its hidden searches and the version list are unchanged. Test in Task 2 (`test_restore_invalid_version_changes_nothing`).
